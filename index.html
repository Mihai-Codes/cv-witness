What the skill asks your agent to check

Keep the useful part of tailoring.

A role can guide which examples you lead with. It shouldn't change what happened, or what you can honestly claim.

01

Give every claim a source

Start with your master resume and details you've confirmed. Mark missing information for review instead of inventing a metric. Check a public pull request's merge state before describing it as merged.

02

Write about your work

Choose relevant examples, then describe them naturally. The overlap script points out repeated phrases so you can review them in context. A common technical term doesn't need rewriting just to look different.

03

Inspect the exported file

The workflow calls for text extraction, page-count and placeholder checks after rendering. It also asks for a visual review. These reduce formatting risk; they do not certify an ATS result.

04

Keep personal files out of Git

Your foundation.md resume and provenance.md verification notes are excluded from version control. Your agent provider's privacy policy still applies when it reads them.

The workflow

Review first. Export when it's ready.

You keep the final say on the facts and wording. The skill provides the instructions and local tools for your agent to follow.

  1. Choose the facts

    Share a posting and a resume source. Your agent selects relevant work, checks supported claims and asks about anything missing.

  2. Review the draft

    Read the proposed wording before an application file is produced. Fix details that don't sound like you, and resolve any placeholders.

  3. Inspect the export

    Use the local PDF workflow or a supported document-authoring path. Check the text and layout before you send it.

Get started

Bring it to your agent.

Choose your host, add the skill, then ask for a draft based on your real experience.

The local PDF renderer currently targets macOS and needs a Chromium-based browser. Review tools use Python 3 and Poppler's pdftotext and pdfinfo. GitHub CLI is used when checking public contributions.

Rezi can be an optional resume source. Amazon Quick is an optional DOCX workflow; the skill does not bundle either service.

Before you use it

Will this pass every ATS?

No. Parsers and employer configurations differ. The text-based layout and export checks help catch formatting problems, but they cannot guarantee correct parsing, a ranking or an interview.

Does this page process my resume?

No. This is a product overview with fictional illustrations, not a resume editor or upload form. The skill runs through your chosen agent. That provider's privacy and data policies apply to any sources you share with it.

Can it sound exactly like me?

The workflow asks for plain language and your review of the draft. Personal voice-corpus support is still on the roadmap; exact voice matching isn't a current guarantee.

Do I need a paid resume service?

The skill is MIT licensed and does not require Rezi or Amazon Quick. You still need an agent host, and any charges or requirements of that host are separate.
